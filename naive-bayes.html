텍스트 분류 문제

텍스트 분류의 과제들

텍스트 분류 (text classification) : 문서 와 class 집합 가 주어지면 알맞은 class 하나를 출력

문서 = 문장, 문단, 책, 리뷰 등 분류 대상 텍스트 단위

분류기 (classifier) : 텍스트를 받아 label 하나를 돌려주는 상자

슬라이드의 과제

  • spam 탐지 : spam인지 아닌지
  • 저자 식별 (authorship identification) : 글을 누가 썼는가
    • Federalist Papers : 1787\~1788년 Hamilton, Madison, Jay가 익명으로 쓴 에세이
    • 12편은 저자가 Hamilton인지 Madison인지 불분명 → 1963년 Mosteller와 Wallace가 Bayesian 방법으로 해결
  • 언어 식별 (language identification) : 포르투갈어인지 영어인지 등
  • 감성 분석 (sentiment analysis) : 리뷰가 positive인지 negative인지 (사람이 다 못 읽어 자동 분류 필요)
  • 주제 분류 : MEDLINE 논문을 MeSH 범주(Drug Therapy, Epidemiology 등)로 분류

공통 틀 : 입력 = 텍스트, 출력 = 미리 정해진 class 하나

규칙 기반 분류와 지도 학습

규칙 기반 : 사람이 규칙을 직접 작성

  • spam이면 dollar, million, lotto 같은 blacklist 단어가 나올 때 spam
  • 도메인이 좁고 전문가가 잘 다듬으면 정확도가 높을 수 있음

문제 : 입력이 너무 다양하고 spam 수법도 정교해짐 → 키워드를 끝없이 늘려야 함

규칙이 너무 literal → high-precision, low-recall이 되기 쉬움

지도 학습 (supervised learning) : label 붙은 을 주면 모델이 파라미터를 스스로 조정
  • 결과 = 문서를 class로 보내는 함수

규칙 기반 vs 지도 학습

항목규칙 기반지도 학습
기준을 만드는 쪽사람이 규칙 작성모델이 label 데이터에서 학습
필요한 것도메인 전문 지식label 붙은 학습 문서 개
약점작성·유지 비용, low-recalllabel 데이터 필요, 편향을 그대로 배움
비유knob을 손으로 돌려 맞춤입출력을 주면 knob을 자동 조정

지도 학습 분류기 : Naive Bayes(이번 강의), logistic regression, neural network, k-NN

요즘은 pretrained LM을 fine-tune하거나 prompt로 분류 → 일부 도메인에서만 아직 NB 사용

Naive Bayes 분류기의 구조

Bag of words 표현

문서를 단어로 잘라 가방(bag)에 넣고 각 단어가 몇 번 나왔는지만 봄

n-gram LM과 달리 token 사이 의존 관계를 전혀 안 봄

문서의 표현 = count 표 (seen 2, sweet 1, whimsical 1, recommend 1, happy 1 ...) → 분류기 는 표만 보고 class를 냄

단어 순서가 사라짐 : I love this fun film과 film fun this love I는 구별 불가

Bayes rule과 MAP 분류

알고 싶은 것 : 문서 가 주어졌을 때 각 class의 확률 (예 : positive 0.7, negative 0.3 → positive)

직접 추정이 어려움 → Bayes rule로 변환

MAP (maximum a posteriori) : 사후 확률이 가장 큰 class

: 문서를 보기 전의 class 비율 = prior

: class가 일 때 이런 문서가 나올 확률 = likelihood

: 어느 class를 고르든 같은 값 → 비교만 하므로 버림

문서를 특징 (단어들)으로 표현하면 아래 꼴

를 버렸으므로 확률이 아니라 비교용 점수 (두 class 점수를 합으로 나누면 상대 확률)

독립 가정과 Naive Bayes 분류기

는 그대로 추정 불가 → 길이 인 단어열의 수 = 어휘 크기의 제곱 → 데이터에서 셀 수 없음

그래서 두 가정

  • Bag of words : 단어의 위치는 중요하지 않음 (버리는 정보 : 어순과 문맥)
  • 조건부 독립 (conditional independence) : class가 주어지면 각 단어 확률 는 서로 독립 (버리는 정보 : 단어 사이의 상관)

positions : 테스트 문서의 모든 단어 위치 (같은 단어가 세 번 나오면 세 번 곱함)

추정할 파라미터 = class마다 단어 하나당 하나

현실의 단어는 독립이 아님 → naive(순진)라는 이름

generative model 그림 : class(예 : China)가 먼저 정해지고 단어 \~(Shanghai, and, Shenzhen, issue, bonds)가 서로 독립으로 하나씩 생성

파라미터 추정과 smoothing

Prior와 likelihood 추정, mega-document

학습 데이터의 빈도로 추정 (maximum likelihood estimate)

: class가 인 학습 문서 수, : 전체 학습 문서 수

예 : 이메일 10개 중 spam 3개 → ,

분자 : class 문서 전체에서 가 나온 횟수

분모 : 같은 문서들의 모든 단어(어휘 ) 횟수 합

mega-document : class 의 모든 문서를 이어 붙인 하나의 긴 문서 → 그 안에서 단어 빈도를 셈
  • 문서 경계가 의미 없음 → 토큰이 많은 긴 문서가 더 많이 반영됨

0 확률 문제와 add-1 smoothing

positive 학습 문서에 fantastic이 한 번도 없음 →

테스트 문서에 fantastic이 있으면 positive 점수는 곱 전체가 0 (다른 증거로 상쇄 안 됨)

해결 : 모든 단어 count에 1을 더하는 Laplace (add-1) smoothing (n-gram의 add-1과 같은 아이디어)

분모에 를 더하는 이유 : 모든 단어 count에 1을 더했으니 합에는 단어 종류 수만큼 더해짐

  • → 합이 1로 유지

슬라이드(p.29)는 더하는 값을 로 일반화

: mega-document에서 의 등장 횟수, : mega-document의 전체 단어 수, 이 add-1

Unknown word와 stop word

smoothing 대상 = 어휘 에는 있지만 어느 class 학습 문서에 한 번도 안 나온 단어 (예 : fun의 neg 확률)

unknown word = 어휘에 아예 없는 단어 (예 : with) → 테스트 문서에서 지움 (확률을 곱하지 않음)

  • 별도 모델이 없는 이유 : 어느 class에 unknown word가 많은지 아는 것은 대개 도움이 안 됨
stop word : the, a처럼 아주 자주 나오는 단어

일부 시스템은 빈도 상위 10개나 50개를 학습·테스트 모두에서 제거 → 보통 도움이 안 됨 → 실제 NB는 모든 단어 사용

예전엔 모델 해상도가 낮아 is, to, the의 의미를 못 잡았지만 LLM 시대에는 중요

부정어 처리

부정어는 문장의 극성을 바꿈

  • I really like this movie = 긍정, I really don't like this movie = 부정
  • Don't dismiss this film, Doesn't let us get bored는 부정이 부정적 표현을 뒤집음

bag of words는 like의 count만 봄 → 변화를 못 잡음

baseline : 부정어 뒤부터 다음 문장부호까지 모든 단어 앞에 NOT_

  • didn't like this movie , but I → didn't NOT_like NOT_this NOT_movie but I
  • NOT_like는 like와 별개의 새 단어 → neg class에 많이 나오면 그렇게 학습

출처 : Das and Chen (2001), Pang, Lee, Vaithyanathan (2002)

Naive Bayes의 성질과 언어 모델

Naive Bayes는 그렇게 naive하지 않다

슬라이드 제목 : Naive Bayes is Not So Naive

장점

  • 학습이 count 세기로 끝남 → 매우 빠르고 저장 공간이 적음
  • 적은 학습 데이터에서도 잘 작동
  • 분류에 무관한 feature는 서로 상쇄 → 강건
  • 중요한 feature가 많은 도메인에 잘 맞음 (decision tree는 데이터를 잘게 쪼개는 fragmentation 문제)
  • 독립 가정이 맞으면 Bayes optimal classifier

텍스트 분류의 믿을 만한 baseline, 뒤에서 더 정확한 분류기를 배움

혼동 행렬

필요한 것 : 분류기의 답, 사람이 정한 정답(gold label)

혼동 행렬 (confusion matrix) : 둘을 교차한 표 (열 = gold label, 행 = 시스템 출력)
gold positivegold negative
system positivetrue positive (tp)false positive (fp)
system negativefalse negative (fn)true negative (tn)

이름의 뒷부분(positive, negative) = 모델의 예측, 앞부분(true, false) = 그 예측이 맞았는지 틀렸는지

  • 실제 positive를 positive라 함 → tp, negative라 함 → fn
  • 실제 negative를 positive라 함 → fp, negative로 맞힘 → tn

accuracy = 맞힌 칸의 비율 (100개 중 70개 맞히면 70%)

tn 999,900, fn 100 → accuracy

그러나 pie 이야기를 하나도 못 찾음 → 쓸모없음

class가 불균형하면 accuracy가 속음 → precision과 recall로 나눠 봐야 함

Precision, recall, F1

precision (정밀도) : 시스템이 positive라고 고른 것 중 진짜 positive의 비율
recall (재현율) : 진짜 positive 중 시스템이 찾아낸 비율

항목precisionrecall

분류기의 피해

표현 피해, 검열, 성능 격차

분류기는 NB든 다른 알고리즘이든 피해를 일으킬 수 있음

표현 피해 (representational harm) : 특정 사회 집단을 깎아내리고 부정적 고정관념을 퍼뜨림
  • Kiritchenko와 Mohammad (2018) : 200개 감성 분석 시스템을 이름만 다른 문장 쌍으로 시험
  • I talked to Shaniqua yesterday vs I talked to Stephanie yesterday (아프리카계 vs 유럽계 미국인 이름)
  • 결과 : 아프리카계 미국인 이름에 더 낮은 감성, 더 부정적인 감정 부여
검열의 피해 (harms of censorship) : 독성 탐지(toxicity detection)에서 나타남
  • 혐오 발언·욕설·괴롭힘을 찾는 텍스트 분류, 온라인 콘텐츠 관리에 널리 사용
  • blind, gay 같은 소수 집단 정체성을 언급만 해도 독성으로 오분류 (Park et al. 2018, Dixon et al. 2018 등)
  • 이 집단의 발언이 덜 보임, 글쓴이가 이런 단어를 피하게 될 수 있음

성능 격차의 원인과 대응

성능 격차 (performance disparity) : 데이터·label이 부족한 많은 언어에서 성능이 떨어짐, 영어도 변종에 따라 다름
  • 언어 식별에서 아프리카계 미국인(Blodgett and O'Connor, 2017), 인도(Jurgens et al., 2017) 작성자의 영어 탐지 성능이 더 낮음

원인 3가지 : 데이터(학습 데이터의 편향을 시스템이 증폭), label, 알고리즘(무엇을 최적화하도록 학습되었는가)

대형 LM을 포함해 NLP 전반의 문제 → 모든 경우에 통하는 해결책은 없음, 완화 방법과 benchmark는 연구 중

분류기는 데이터로 학습 → 데이터에 편향·독성·잘못된 개념이 있으면 같은 편향

  • 6, 7년 전 영상 CNN 분류기가 백인 남성에게서 잘 작동한다는 보고 : 데이터가 주로 미국 영어권 중년 남성에게 몰려 있음
  • 예전 데이터의 성별 편향 (아버지는 의사, 어머니는 간호사)을 그대로 반영
  • GPT 같은 LM이 나쁜 질문에 답을 거절하는 것은 이런 내용을 거르는 모델이 안에 있기 때문

그래서 데이터 수집·전처리 단계에서 먼저 걸러야 함
