1페이지 — 표지

Understanding Language-Dependent Quantization Sensitivity in LLMs

제목 뜻: “대규모 언어 모델에서 언어에 따라 달라지는 양자화 민감도 이해하기.”

Quantization sensitivity(양자화 민감도)는 모델을 낮은 비트로 바꿨을 때 성능이 얼마나 변하는지와 관련돼. 같은 압축을 해도 한국어와 영어에서 하락 폭이 다를 수 있다는 문제를 다뤄.

2페이지 — Introduction

원문 핵심: 4-bit quantization reduces LLM(대규모 언어 모델) memory costs, but may affect languages unequally.

뜻: 4비트 양자화는 LLM의 메모리 비용을 줄이지만, 모든 언어의 성능에 같은 영향을 주지는 않을 수 있다는 말이야.

1. Motivation — 왜 연구할까?

  • 4-bit quantization enables more memory-efficient deployment: 대형 모델 가중치를 더 적은 비트로 저장해 메모리 부담을 줄일 수 있어.
  • Prior studies report different performance drops across languages and writing systems: 기존 연구에서 언어 또는 문자 체계에 따라 성능 감소 폭이 다르다고 보고했어.
  • Understanding these gaps matters for reliable multilingual deployment: 여러 언어로 서비스를 제공하려면 어느 언어가 양자화에 더 민감한지 알아야 해.

[추가 설명 — 양자화란?] FP16은 가중치 하나를 16비트로 나타내고, 4-bit는 일반적으로 더 적은 수준의 값으로 나타내는 거야. 따라서 저장 메모리는 줄지만 가중치의 근삿값을 사용하므로 성능이 달라질 수 있어. 단순 계산으로 가중치 10억 개라면 FP16 저장 공간은 약 2GB, 4비트는 약 0.5GB야(실제로는 양자화 관련 메타데이터 등 추가 공간이 필요함).

2. Token-Length Hypothesis — 핵심 가설

  • Equivalent content can require different numbers of tokens across languages: 같은 의미의 질문도 언어마다 토크나이저가 나누는 토큰 수가 다를 수 있어.
  • Longer input sequences may be more sensitive to quantization errors: 토큰 수가 많은 입력에서 양자화에 따른 성능 변화가 더 클 수 있다는 가설이야.
  • Prior studies have not isolated evaluation-time input token(토큰) length: 기존 논문들은 평가할 때의 입력 길이를 별도로 떼어 놓고 검증하지 않았어.

[추가 설명] “같은 문제를 영어로 표현하면 20토큰, 한국어로 표현하면 35토큰”인 상황을 생각하면 돼. 이 숫자는 예시일 뿐 실제 PPT의 측정값은 아니야. 중요한 건 문제의 내용이 아니라 길이 차이가 성능 저하에 영향을 주는지 확인하는 것이야.

3. Goal — 최종 목표

Test whether input token count helps explain language-dependent degradation under 4-bit NF4 quantization.

의미: “4-bit NF4 양자화로 생긴 성능 저하의 언어별 차이를, 입력 토큰 수가 얼마나 설명하는지 검증한다.”

이 페이지 한 줄: 압축하면 언어별 성능이 다르게 떨어지는데, 그 차이가 입력 길이와 관련 있을까?

3페이지 — Related Work: Multilingual Quantization

원문 핵심: Quantization losses differ across scripts and languages.

뜻: 기존 연구에서 문자 체계와 언어에 따라 양자화로 인한 성능 손실이 다르게 나타났어.

1. Marchisio et al. (2024) — 언어 그룹 평균 비교

FP16 대비 평균 점수 변화

모델 라틴 문자 언어 비라틴 문자 언어
103B −0.7% −1.9%
8B −3.0% −3.7%
  • 103B 모델에서는 비라틴 문자 그룹의 감소 폭(−1.9%)이 라틴 문자 그룹(−0.7%)보다 크게 나타나.
  • 8B 모델도 비라틴 문자 그룹에서 더 크게 떨어져(−3.7% vs. −3.0%).
  • 여기서 103B → 8B가 양자화라는 뜻은 아님. B는 billion parameters(10억 개 단위의 파라미터 수)야. 즉 103B(약 1,030억 개)와 8B(약 80억 개)는 서로 다른 크기의 모델이고, 각 모델에서 원본 대비 양자화 성능 변화를 살핀 거야.

2. Thomas (2026) — 영어와 한국어 비교

Qwen2.5-3B, 3-bit GPTQ 사용

지표 영어 한국어
Perplexity(퍼플렉시티) ratio ×1.35 ×3.49
Global-MMLU 64.7 → 41.8 50.0 → 28.1
Absolute drop −22.9 pp −21.9 pp
Relative drop −35.4% −43.8%
  • Perplexity ratio: 양자화 후 perplexity가 원본 대비 몇 배가 되었는지. 보통 perplexity는 낮을수록 좋으니, ×3.49는 ×1.35보다 악화가 더 큰 결과야.
  • Absolute drop(절대 감소): 영어는 64.7에서 41.8로 가므로 22.9 퍼센트포인트(pp) 하락. 한국어는 50.0에서 28.1로 가므로 21.9pp 하락.
  • Relative drop(상대 감소율): 처음 점수 대비 얼마나 떨어졌는가를 보는 방식. 영어는 −35.4%, 한국어는 −43.8%로 한국어의 상대 감소율이 더 커.
  • Key result: 상대 감소율만 보면 한국어가 훨씬 취약해 보이지만, 절대 감소 폭은 22.9pp와 21.9pp로 유사하다는 점을 함께 봐야 해.

Research link(우리 연구와의 연결): 앞선 논문들은 언어별 차이를 보고했지만, 이 격차에 평가 시점 입력 토큰 길이가 얼마나 기여했는지 분리하지 않았어.

주의: Thomas의 3-bit GPTQ는 우리 실험에서 사용할 4-bit NF4와 방식·설정이 달라. 숫자를 우리 실험의 예상 성적처럼 생각하면 안 돼.

4페이지 — Related Work: Possible Explanations

핵심: 언어별 양자화 성능 차이에 대한 두 가지 경쟁 가능 설명이 있다.

H1 — Tokenization(토큰화 가설)

  • Petrov et al. (2023): 동일한 내용도 특정 언어에서는 최대 15배의 토큰을 요구할 수 있다고 보고.
  • 더 긴 시퀀스가 양자화 오류에 더 민감할 수 있음.
  • 기존 연구들은 평가 입력의 토큰 길이 기여를 분리하지 않았음.

쉽게 말하면: 영어 질문과 한국어 질문이 같은 의미더라도, 토큰화 결과의 길이가 다를 수 있어. 그래서 언어 자체 때문이 아니라 토큰 수가 많아서 더 크게 성능이 떨어지는 걸 수도 있다는 주장이지. 이는 검증할 가설이지 이미 증명된 사실이 아니야.

H2 — Calibration(캘리브레이션 가설)

  • GPTQ와 AWQ는 calibration(캘리브레이션) inputs를 이용해 양자화 파라미터를 결정함.
  • 영어 중심 캘리브레이션은 영어 데이터에서 주로 나타나는 activation(활성화 값) 분포에 유리할 수 있음.
  • Chimoto et al. (2026): 다국어 캘리브레이션으로 perplexity가 최대 3.52포인트 개선되었다고 보고.

쉽게 말하면: 양자화 전에 영어 데이터를 주로 보여줬다면, 영어 입력을 잘 처리하도록 압축 설정이 정해지고 한국어 입력에서 불리할 수 있다는 설명이야.

Takeaway

Language-level gaps alone cannot distinguish these two explanations.

영어와 한국어의 정확도 하락만 봐서는 토큰 길이가 원인인지(H1) 또는 캘리브레이션 데이터 구성이 원인인지(H2) 구별할 수 없어.

[추가 설명] Calibration Input Data를 왜 사용할까?

캘리브레이션 입력 데이터 = 양자화 방법이 참고하는 대표 샘플 입력이야.

  1. 대표 문장이나 질문을 FP16 모델에 입력한다.
  2. 모델 내부에서 나타나는 activation과 값의 특성을 관찰한다.
  3. 그 정보를 활용하여 저비트로 표현할 가중치의 양자화 설정을 결정한다.
  4. 그 설정에 따라 양자화된 모델을 만든다.

왜 필요하지? 4비트로 줄이면 표현 가능한 값의 종류가 제한되어 오차가 생겨. 대표 입력에서 중요한 정보가 손상되지 않게 설정을 정하려는 거야. GPTQ와 AWQ는 내부 알고리즘이 동일한 것은 아니지만, 둘 다 대표 입력을 활용하는 계열이야.

왜 언어가 영향을 주지? 영어로만 설정을 정하면 영어 activation 특성에 맞춰진 설정이 다른 언어에 최적이 아닐 수 있어. 다만 언어 차이의 원인이 반드시 캘리브레이션이라는 뜻은 아님.

5페이지 — Research Gap & Question

원문 핵심: Prior work(이전 연구) has not isolated evaluation-time token length as a predictor of degradation.

뜻: 기존 연구에서 양자화 성능 저하를 설명할 때, 평가 입력 길이가 갖는 역할을 독립적으로 확인하지 않았다는 거야.

1. What Prior Work Leaves Open — 어떤 부분이 비어 있을까?

  • Marchisio: 언어 그룹별 평균만 비교했으며 입력 토큰 수를 측정하지 않음.
  • Chimoto: 캘리브레이션 데이터를 달리했지만 평가 시점 입력 길이의 역할은 분리하지 않음.
  • Thomas: 3-bit GPTQ의 언어별 결과를 봤지만 토큰 길이의 기여를 분리하지 않음.

2. How Our Study Tests H1 — 우리 연구는 어떻게 검증할까?

  • NF4: 별도의 calibration dataset이 필요 없는 양자화 방식을 택해 캘리브레이션 데이터 언어 선택에 의한 편향을 피함.
  • Global-MMLU: 영어와 한국어에서 같은 question ID를 사용해 질문 내용을 대응시킴. 완전히 무관한 문제를 비교하는 일을 피하기 위함이야.
  • Qwen2.5-3B-Instruct: Thomas와 모델 계열과 규모가 유사하되, 모델 변형과 양자화 방식은 다름.

3. RQ — Research Question

Does input token length predict degradation under 4-bit NF4 quantization?

“4-bit NF4 양자화에서 입력 토큰 길이가 성능 저하를 예측할 수 있는가?”

핵심 연결: 앞 페이지에서 제시한 H1(토큰화 가설)을 검증하기 위해, H2의 한 요소인 캘리브레이션 샘플 선택을 배제하는 설계를 쓰는 거야. NF4를 쓴다고 해서 모든 언어 편향이 없어지는 건 아님.

6페이지 — Methodology: Experimental Setup

목표: 실험할 모델, 데이터셋, 비교 조건과 평가 지표를 정하는 페이지.

1. Model

  • Qwen2.5-3B-Instruct: 실제 비교에 사용할 약 3B 규모의 지시 수행형 모델.
  • FP16 baseline(베이스라인) vs. NF4 4-bit: 같은 모델의 FP16 기준선과 4비트 NF4 모델을 비교하여 양자화의 영향을 측정.

2. Dataset

  • Global-MMLU: 언어별로 대응하는 객관식 문제들을 사용하는 데이터셋.
  • English / Korean: 기본 비교 언어는 영어와 한국어.
  • Vietnamese (optional): 베트남어는 선택적으로 확장.

3. Evaluation

  • Accuracy: 답을 맞힌 문항의 비율. 실제 정답률이 얼마나 낮아지는지 확인.
  • Log probability of the correct answer: 모델이 정답에 얼마나 높은 확률을 주는지 로그 척도로 평가. 정답 여부가 같아도 모델의 확신 정도가 변할 수 있다는 점을 추가로 살펴볼 수 있어.
  • Input token count: 입력이 토크나이저를 통과한 뒤 몇 개의 토큰이 되는지 측정. 바로 이 값이 핵심 분석 변수야.

4. Shared Protocol

  • Same tokenizer, prompt(프롬프트), scoring rules: 토크나이저, 프롬프트 형식, 채점 규칙을 같게 유지해 다른 조건 때문에 점수가 달라지지 않도록 함.
  • Small-scale experiments on Google Colab: Colab에서 소규모로 실험할 계획.

이 페이지 한 줄: “FP16 vs NF4를 영어·한국어의 대응 문제로 시험하고, 성능 감소와 입력 토큰 수를 함께 기록하겠다.”

7페이지 — Experiment 1: Language-Level Comparison

질문: Does 4-bit quantization degrade performance differently across languages?

뜻: “4비트 양자화에 따른 성능 저하가 언어마다 다른가?”

Procedure — 실험 절차

  1. Global-MMLU에서 영어와 한국어의 동일 question ID를 선택한다.
  2. 각 질문을 FP16 모델과 NF4 모델 모두에 넣는다.
  3. 프롬프트 형식과 채점 기준은 고정한다.
  4. 언어별 accuracy와 correct-answer log probability의 변화를 비교한다.

Comparison — 무엇을 계산할까?

Quantization penalty = NF4 score − FP16 score

[추가 설명용 가상 예시]

  • 어떤 언어의 FP16 정확도가 80%, NF4 정확도가 70%라면: 70 − 80 = −10pp.
  • 다른 언어에서 같은 계산이 −4pp라면, 첫 언어가 더 큰 감소를 보인 셈이야.
  • 이 값들은 설명을 위한 숫자일 뿐, PPT의 실험 결과는 아님.

중요: Experiment 1에서 확인하는 것은 언어별 차이가 있는가야. 왜 차이가 생겼는지는 아직 판단하지 않아. 그 이유를 살펴보는 게 Experiment 2야.

8페이지 — Experiment 2: Token-Length Controls

질문: Is the language gap explained by differences in token count?

뜻: “언어별 양자화 성능 저하 차이가 토큰 수의 차이로 설명되는가?”

Control A — Cross-Language Matching(언어 간 길이 맞추기)

  • 동일한 토크나이저로 각 영어·한국어 질문의 토큰 수를 측정한다.
  • 두 언어에서 토큰 길이가 유사한 질문들끼리 비교한다.

왜 할까? 토큰 수가 큰 원인이라면, 입력 길이를 비슷하게 맞춘 뒤에는 영어·한국어의 성능 차이가 작아지는지 확인할 수 있어.

Control B — Within-Language Paraphrasing(동일 언어에서 바꿔 쓰기)

  • 질문의 의미와 정답을 유지한다.
  • 표현을 바꿔 토큰 길이가 다르게 만든다.

[추가 설명] 같은 내용을 한 문장으로 짧게 묻거나 좀 더 풀어서 길게 묻는 경우를 비교한다고 생각하면 돼. 영어와 한국어의 언어 차이 없이도 길이 변화가 NF4 penalty와 연결되는지 살펴보려는 설계야.

Analysis — 무엇을 확인할까?

  1. 토큰 수가 많아질수록 NF4 penalty(성능 저하)가 커지는가?
  2. 길이를 매칭했을 때 언어별 성능 저하 격차가 줄어드는가?

실험 1과 비교: Experiment 1은 “영어와 한국어가 다르게 떨어지나?”를, Experiment 2는 “그 차이가 길이 때문일 수 있나?”를 묻는다는 차이가 있어.

9페이지 — Experiment 3 (Optional): Hidden-State Analysis

질문: Do FP16 and NF4 representations diverge more for longer inputs?

뜻: “입력이 길어질수록 원본과 양자화 모델의 내부 표현 차이가 더 커질까?”

Procedure

  1. FP16과 NF4 모델에 동일한 입력을 사용한다.
  2. 두 모델에서 대응하는 Transformer(트랜스포머) layer의 hidden state(은닉 상태)를 추출한다.
  3. 같은 토큰 위치의 hidden state 사이에서 cosine distance를 계산한다.

Analysis

  • Layer depth: 몇 번째 Transformer 층인지에 따라 차이를 비교.
  • Input length: 입력이 길 때와 짧을 때 차이를 비교.
  • Representation drift: 두 모델의 내부 표현이 얼마나 달라졌는지 보는 것.

[추가 설명] Hidden state는 각 층에서 토큰을 수치 벡터로 표현한 결과야. Cosine distance는 두 벡터 방향의 차이를 수치화하는 방법이야. 양자화된 모델의 벡터가 원본과 더 달라진다면 내부 표현이 변화했다고 볼 수 있어.

PPT의 주의 문구: This measures representation differences, not causal error accumulation. 즉, 표현의 차이를 측정할 뿐 오류가 층이나 토큰을 따라 인과적으로 누적된다고 증명하는 실험은 아니야.

Optional: 이 세 번째 실험은 제안서에서 선택적 확장이야.

10페이지 — Analysis and Expected Interpretation

핵심: 실제 결과를 보여주는 페이지가 아니라, 실험 결과가 어떻게 나오면 무엇을 의미하는지 미리 정해 둔 페이지야.

1. If token count explains the language gap

“입력 토큰 수가 언어별 차이를 설명한다면?”

  • 입력이 길수록 더 큰 quantization penalty가 나타날 것.
  • 토큰 길이가 비슷한 질문끼리 비교하면 언어 간 차이가 줄어들 것.
  • (선택) 입력이 길수록 representation drift가 커질 수 있음.

의미: 토큰 수가 언어별 양자화 민감도 차이를 설명하는 중요한 변수라는 근거가 되는 거야.

2. If the language gap remains

“토큰 길이를 맞춰도 언어별 차이가 계속 남는다면?”

  • 토큰 수만으로는 결과를 충분히 설명하기 어려움.
  • 언어적 특성이나 모델 자체의 다른 요인들이 영향을 미칠 수 있음.

의미: 길이가 전혀 상관없다고 자동 결론 내리는 것은 아니고, 적어도 길이 하나만으로 전체 격차를 설명하기 부족하다는 뜻이야.

3. Contribution

Directly test a proposed mechanism instead of only reporting a performance gap.

“언어별 성능 차이가 있다”고 보고하는 데서 끝나지 않고, 그 차이를 설명하는 가설인 입력 토큰 길이를 실제로 분리하여 검증하려는 것이 연구의 기여야.
