텍스트 전처리와 정규식

입력 텍스트는 코퍼스에서 온다

NLP 시스템 : 텍스트 입력 → 모델 처리 → 텍스트·레이블 출력

입력은 코퍼스(corpus) 에서 옴 = 위키백과, 소설, 신문, 이메일 같은 텍스트 모음

코퍼스는 정리 전 상태 → 필요한 정보를 뽑아 가공하는 전처리가 먼저 → 정규식·토큰화가 그 도구

정규식은 범용 해법이 아니라 텍스트를 다루는 도구 → 필요할 때 온라인 튜토리얼을 찾아 쓰면 됨

정규식 (regular expression) : 텍스트 문자열을 지정하는 형식 언어(formal language)

동기 질문 : woodchuck, woodchucks, Woodchuck, Woodchucks, Groundhog, groundhogs를 모두 찾으려면?

  • 대소문자, 단수·복수, 다른 이름이 섞임 → 아래 연산자로 한 식에 묶음

정규식의 기본 연산자

대괄호 disjunction과 범위

대괄호 안에 글자를 나열 → 그중 한 글자에 맞음 (대괄호 하나 = 글자 한 칸)

  • [wW]oodchuck → Woodchuck, woodchuck
    [1234567890] → 숫자 한 글자

범위는 하이픈 : [A-Z] 대문자, [a-z] 소문자, [0-9] 숫자 (일일이 나열할 필요 없음)

대괄호 안의 부정

^가 대괄호 첫 글자 → 목록을 부정

  • [^A-Z] 대문자 아님, [^Ss] S도 s도 아님, [^.] 마침표 아님
    Oyfn pripetchik에서 [^A-Z]가 처음 잡는 글자 = O 다음의 y

^가 첫 자리가 아님 → 부정 X, ^ 문자 그대로 ([e^]는 e 또는 ^)

대괄호 안에서는 ., *, +, ?도 특수 의미를 잃음 → [.]은 마침표 한 글자만

축약 표기(alias)

\d = [0-9] 숫자 ↔ \D 숫자 아님
\w = [a-zA-Z0-9_] 영문자·숫자·밑줄 ↔ \W 영문자·숫자·밑줄 아님 (Look!의 느낌표)
\s = 공백, 탭, 줄바꿈 ↔ \S 공백 아님
\w에 밑줄 포함 → 뒤의 the 찾기에 영향

  • 슬라이드의 확장형은 ASCII 글자 기준

파이프를 쓴 disjunction

| : 여러 글자짜리 덩어리 중 하나 (groundhog|woodchuck, yours|mine)

대괄호 = 한 글자 안의 선택 vs 파이프 = 문자열 덩어리 사이의 선택 (a|b|c = [abc])

#동기 질문의 답 = 둘의 조합

  • [gG]roundhog|[Ww]oodchuck → groundhog, Groundhog, woodchuck, Woodchuck (선택지 4개)

와일드카드, 선택, 반복

beg.n : .은 임의의 글자 한 개 → begin, begun, beg3n, beg n
woodchucks? : ?는 바로 앞 글자가 있어도 없어도 됨 → woodchuck, woodchucks

to* : *는 바로 앞 글자가 0번 이상 → t, to, too, tooo
to+ : +는 바로 앞 글자가 1번 이상 → to, too, tooo (t만 있는 것은 제외)

  • .은 공백도 한 글자 → beg n까지 잡음
  • * vs + : o가 하나도 없는 경우(t 혼자)를 *는 포함, +는 제외
    • 반복 연산자는 바로 앞 한 글자 또는 괄호로 묶은 덩어리에 적용

앵커

^, $ : 글자가 아니라 위치 (^ 줄의 시작, $ 줄의 끝)

^[A-Z] : 대문자로 시작 (Palo Alto의 P)

\.$ : 마침표로 끝 (The end.), .$ : 아무 글자로 끝 (The end? The end!)

문자 그대로의 마침표 = \.

^[^A-Za-z] : 앞의 ^ = 줄의 시작, 대괄호 안의 ^ = 부정 → 알파벳이 아닌 글자로 시작 (1 "Hello")

연산자 우선순위

순서 : 괄호 → 반복(*, +, ?) → 글자 나열·앵커 → |

|가 가장 약하게 묶임 → the|any = the 또는 any (thany X), 원하면 th(e|a)ny

ab* : b 0개 이상 (abbb) vs (ab)* : ab 덩어리 반복 (abab)

(?:some|a few)의 괄호도 |의 범위를 정하려는 것

the 찾기 : 오류를 보며 식을 고치는 과정

정규식은 틀린 결과를 보며 고치는 반복 과정으로 완성

the, The, other, Theology, there, then에 각 패턴 적용 (앞뒤 공백 포함)

패턴theTheotherTheologytherethen
theOXOXOO
he		OOOOOO
\\W
he\\W		OOXXXX

the : The를 놓침, [tT]he : other, Theology, there, then 속 the까지 잡음

\W[tT]he\W : 앞뒤에 영문자·숫자·밑줄이 아닌 글자를 요구 → 단어 경계 역할

빈틈 : \W는 글자를 소비 → 문자열 맨 앞·끝의 The는 못 잡음 (The end에서 실패)

  • 해결 : (^|\W)[tT]he(\W|$) 또는 \b[tT]he\b<br>\w에 숫자·밑줄 포함 → the2, the_ 안의 the는 경계로 인정 X

false positive와 false negative

false negative : 잡아야 할 것을 못 잡음
  • the 예 : the가 The를 놓침
    고치는 방향 : 패턴을 넓힘 → recall ↑
false positive : 잡지 말아야 할 것을 잡음
  • the 예 : [tT]he가 there, then, other를 잡음
    고치는 방향 : 패턴을 좁힘 → precision ↑

두 오류는 줄이는 방향이 반대 → 한쪽을 고치면 다른 쪽이 늘 수 있음
텍스트 분류(text classification)에서 다시 나옴

치환과 capture group

치환 : s/regexp1/pattern/ (Python, UNIX 명령 공통), 예 : s/colour/color/

  • ⇒ regexp1 을 pattern 으로 바꿈.

목표 : the 35 boxes → the <35> boxes

  • 괄호로 묶으면 번호 붙은 저장소(register)에 저장 → \1로 꺼냄 (괄호 없으면 저장 X)
  • s/([0-9]+)/<\1>/
    • [0-9]+가 35를 잡음 → 괄호가 1번 register에 저장 → <\1>이 꺾쇠로 감싸 출력

\1에는 식이 아니라 그 순간 실제로 매치된 인스턴스(35)가 들어감
괄호가 여러 개 → \1, \2

/the (.*)er they (.*), the \1er we \2/ : 뒷절이 앞절과 같은 내용이어야 매치
the faster they ran, the faster we ran : \1 = fast, \2 = ran → 매치
the faster they ran, the faster we ate : \1 = fast, \2 = ran이어야 하는데 ate가 옴 → 매치 실패

저장하지 않는 괄호

괄호 = 묶기 + 저장 → 묶기만 하려면 (?:...)

/(?:some|a few) (people|cats) like some \1/

  • 첫 괄호는 선택용, 저장 X → (people|cats)가 1번 register
    some cats like some cats → \1 = cats → 매치
    some cats like some some → 끝이 some ≠ cats → 불일치
    • 일반 괄호 (some|a few)로 바꾸면 \1 = some → 결과가 뒤집힘

룩어헤드

lookahead : 현재 위치 뒤를 미리 확인만 하는 조건
  • (?= pattern) : 뒤에 pattern이 오면 참
    (?! pattern) : 뒤에 pattern이 오지 않으면 참

너비 0 → 글자를 소비하지 않음 → 이어지는 식이 같은 자리에서 다시 시작

  • 소비 : 정규표현식이 문자를 읽고 다음 위치로 이동한다는 말.

/^(?!Volcano)[A-Za-z]+/ : Volcano로 시작하지 않는 줄의 첫 단어

  • Volcano로 시작 → 룩어헤드 거짓 → 전체 실패

정규식만으로 만든 대화 시스템 ELIZA

ELIZA : 1966년 Joseph Weizenbaum의 초기 NLP 시스템, 로저스식 심리상담사를 흉내

규칙은 모두 s/.* 패턴 .*/응답/ 형태의 치환

  • I'M (depressed|sad) → I AM SORRY TO HEAR YOU ARE + \1<br>all 포함 → IN WHAT WAY?
    always 포함 → CAN YOU THINK OF A SPECIFIC EXAMPLE?
    • 이해 없이 입력을 규칙대로 바꿀 뿐인데 사용자는 이해받는 느낌
      요즘은 대화의 종류가 너무 많아 규칙 방식은 통하지 않음

단어와 코퍼스

단어를 세는 기준 : lemma와 wordform

토큰화의 첫 질문 : 문장에 단어가 몇 개인가

I do uh main- mainly business data processing → 끊긴 단어(main-)·군말(uh)을 단어로 셀지
Seuss's cat in the hat is different from other cats! → cat과 cats를 같은 단어로 볼지

lemma : 어간, 품사, 대략적 어휘 의미가 같은 기본형
wordform : 활용이 반영된 표면 형태
  • cat과 cats → lemma 같음, wordform 다름

type과 token

type : 어휘(vocabulary)에 들어 있는 서로 다른 단어 하나
  • 슬라이드 예 : the는 type 하나
token : 실제 문장에 나타난 type의 인스턴스 하나
  • 슬라이드 예 : the가 두 번 나오면 token 둘

예문 : they lay back on the San Francisco grass and looked at the stars and their

  • token 15개, the·and가 두 번씩 → type = 15 − 2 = 13개

세는 기준별 token / type

기준tokentype
공백으로 나눈 그대로1513
San Francisco를 한 단어로 취급1412
거기에 they와 their도 같은 단어로 취급1411

기준에 따라 답이 달라짐 → 어떤 기준으로 셌는지 밝혀야 함

코퍼스가 커지면 어휘도 커진다 : Heaps' law

Heaps' law (Herdan's law)

: type 수(어휘 크기), : token 수, , : 코퍼스에 따른 상수

는 보통 0.67과 0.75 사이 → 어휘 크기는 token 수의 제곱근(지수 0.5)보다 빠르게 늘어남

지수 0.67, 0.75 : token 2배 → type 약 1.59배, 1.68배 / token 10배 → 약 4.68배, 5.62배 (제곱근이면 3.16배)

셰익스피어(token 884,000, type 31,000) → COCA(token 4억 4천만, type 200만)

  • 지수 ≈ 0.67
  • , → COCA type 약 199만 개 (표의 200만과 거의 같음)

수식 암기는 불필요, token이 많아지면 type도 늘어난다는 경향만 알면 됨

코퍼스는 목적이 있는 데이터다

텍스트 = 특정 작성자가 특정 시기에 특정 언어·변종(variety)으로 특정 기능을 위해 쓴 것

코퍼스가 달라지는 축 : 언어(세계에 7097개), 변종(African American Language, 트위터의 iont = I don't), 장르(뉴스, 소설, 논문, 위키백과), 작성자 인구통계

코드 전환 (code switching) : 스페인어·영어처럼 한 문장 안에서 두 언어를 섞어 씀

대화 시스템을 만든다면 뉴스 코퍼스가 아니라 대화 코퍼스

코퍼스 datasheet (Gebru et al., 2020) : 동기, 상황, 수집 과정, 주석, 인구통계를 확인

한 출처에 치우친 코퍼스(의학 논문 등)는 편향 가능

텍스트 정규화의 세 단계

모든 NLP 작업은 텍스트 정규화 (text normalization) 를 거침

세 단계 :
토큰화(tokenizing) → 표기 통일(normalizing word formats) → 문장 분할(segmenting sentences)

case folding : 대소문자 통합, 표기 통일의 가장 간단한 예
  • tr 'A-Z' 'a-z' → The와 the가 합쳐져 빈도가 모임
    US와 us처럼 의미가 갈리면 항상 합치는 게 정답은 아님

문장 분할의 어려움 : 마침표가 줄임말 안에서도 쓰임 (m.p.h., Ph.D.)

stemming vs lemmatization

항목stemminglemmatization
방식단어 끝 접사를 규칙으로 잘라냄품사 등을 고려해 사전의 기본형을 찾음
결과실제 단어가 아닐 수 있음 (Porter : ponies는 poni, studies는 studi)실제 단어 (am, are, is는 be, cats는 cat)
비용단순하고 빠름형태 분석이 필요해 상대적으로 무거움

규칙 기반 토큰화

공백 기준 토큰화와 Unix 도구

공백으로 단어가 구분되는 문자 체계(아랍, 키릴, 그리스, 라틴 문자) → 공백 사이를 자른 것이 가장 단순한 토큰화

슬라이드 : "UNIX for Poets"의 tr 파이프라인으로 단어·빈도 추출 (수업에서는 건너뜀)

tr 파이프라인 단계별 출력

1단계 : tr -sc 'A-Za-z' '\n' < shakes.txt : 알파벳 아닌 글자를 줄바꿈으로(-c 보집합, -s 연속 압축)

  • 출력 : THE, SONNETS, by, William, ...

2단계 : sort : 같은 단어를 이웃하게 정렬

  • 출력 : A가 줄줄이 반복

3단계 : uniq -c : 이웃한 같은 줄을 세어 합침

  • 출력 : 1945 A, 72 AARON, 19 ABBESS, 5 ABBOT

4단계 : 앞에 tr 'A-Z' 'a-z', 뒤에 sort -n -r : 소문자 통합 + 빈도 내림차순

  • 출력 : the 23243, i 22225, and 18618, to 16339, of 15687, a 12780, you 12163, my 10839, in 10005, d 8954

d가 8954번 : I'd가 아포스트로피에서 I와 d로 갈라짐

구두점을 그냥 지울 수 없는 이유

알파벳 연속 [A-Za-z]+만 남기면 아래처럼 깨짐

  • 줄임말 m.p.h. → m, p, h
    학위 Ph.D. → Ph, D
    회사명 AT&T → AT, T
    축약 cap'n → cap, n
    가격 $45.55 → 아무것도 안 남음
    날짜 01/02/06 → 아무것도 안 남음
    URL http://www.stanford.edu → http, www, stanford, edu
    해시태그 #nlproc → nlproc (표시가 사라짐)
    이메일 someone@cs.colorado.edu → someone, cs, colorado, edu

이 항목들은 하나의 token으로 남아야 의미 보존

clitic : 혼자 서지 못하고 다른 단어에 붙는 단어 (we're 안의 are, 프랑스어 j'ai의 je)
다단어 표현 (MWE) : New York, rock 'n' roll을 한 단어로 볼지 두 단어로 볼지

공백 분리만으로 부족 → 정규식으로 이 모든 경우를 토큰화할 수 있음

NLTK의 regexp_tokenize

입력 : That U.S.A. poster-print costs $12.40...

대안(|로 이어진 패턴)을 위에서부터 차례로 시도

  • 순서 1 : ([A-Z]\.)+ : 대문자+마침표 반복 약어 (U.S.A.)
    순서 2 : \w+(-\w+)* : 내부 하이픈 허용 단어 (That, poster-print, costs)
    순서 3 : \$?\d+(\.\d+)?%? : 통화·퍼센트 ($12.40)
    순서 4 : \.\.\. : 줄임표 (...)
    순서 5 : 구두점 대괄호 문자 집합 : 따로 분리할 구두점 (쉼표, 물음표, 괄호 등)

결과 : ['That', 'U.S.A.', 'poster-print', 'costs', '$12.40', '...']

  • 공백으로만 나눔 → 마지막이 $12.40...으로 붙음
    \w+만 사용 → U, S, A와 poster, print, 12, 40으로 쪼개짐
    \w+(-\w+)*를 약어보다 앞에 둠 → U.S.A.가 U, 점, S, 점, A, 점으로 갈라짐

앞쪽 대안이 먼저 시도됨 → 구체적인 패턴을 앞에 둬야 함

최신 NLTK에서 슬라이드 코드를 그대로 실행하면 capture group 때문에 튜플로 나옴 → 괄호를 (?:...)로 바꿔야 슬라이드와 같음

공백이 없는 언어

중국어, 일본어, 태국어는 공백으로 단어를 구분하지 않음 → token 경계부터 정해야 함

중국어 단어 = 한자(hanzi) 구성, 한자 하나 = 형태소(morpheme) 하나, 한 단어 평균 2.4개 한자, 단어에 대한 합의는 없음

슬라이드 예문 : 姚明进入总决赛 ("Yao Ming reaches the finals")

  • 단어 단위 : 3개 → 姚明, 进入, 总决赛
    더 잘게 : 5개 → 姚, 明, 进入, 总, 决赛
    글자 단위 : 7개 → 姚, 明, 进, 入, 总, 决, 赛

서브워드 토큰화

단어·글자 단위의 한계

단어 단위 : 어휘에 want까지만 있으면 I wanted to go out...의 wanted = unknown (사람은 뜻을 아는데 토크나이저는 모름)

  • 장점 : token이 의미를 가짐 / 단점 : 어휘 밖 단어 처리 불가

글자 단위 : wanted → w, a, n, t, e, d → unknown 없음, 하지만 글자에 의미가 없어 조합 의미를 모델이 다 이해해야 하고 오래 걸림

  • 장점 : unknown이 없음 / 단점 : 의미 없는 글자, 긴 시퀀스

해결책은 중간 : 서브워드

서브워드 (subword) : wanted → want + ed(과거형 어미)
  • 장점 : 어휘 밖 단어도 아는 조각으로 표현 / 단점 : 조각을 데이터에서 학습해야 함

분할은 사람이 정한 규칙이 아니라 데이터에서 빈도 기준으로 학습

transformer 계열 모델은 모두 서브워드 토큰화를 사용

세 가지 알고리즘과 learner, segmenter

대표 알고리즘 3가지

  • Byte-Pair Encoding (BPE, Sennrich et al., 2016)
    Unigram language modeling tokenization (Kudo, 2018)
    WordPiece (Schuster and Nakajima, 2012)

모두 두 부분으로 구성

  • token learner : 원본 학습 코퍼스 → 어휘(token 집합) 생성
    token segmenter : 새 문장 → 어휘에 맞게 토큰화

수업에서는 BPE와 WordPiece만 다룸, Unigram은 이름만 나옴

BPE (Byte-Pair Encoding)

학습 알고리즘

1단계 : 단어를 글자로 쪼갬 → 서로 다른 글자가 처음 어휘
2단계 : 크기 2 window를 밀며 이웃한 쌍을 셈 (단어 빈도만큼 곱함)
3단계 : 가장 자주 나오는 쌍을 병합 → 어휘 추가, 코퍼스의 해당 쌍을 모두 새 기호로 바꿈
4단계 : 번 병합할 때까지 반복 → 최종 어휘 크기 = 처음 글자 수 + (멈추는 기준 = 어휘 크기나 반복 횟수, 구현마다 다름)

WordPiece

초기화와 점수 함수

첫 글자는 그대로, 나머지 글자 앞에 ## : learning → l ##e ##a ##r ##n ##i ##n ##g

처음 어휘 13개 : ##a, ##c, ##e, ##f, ##g, ##i, ##n, ##r, ##s, ##u, f, h, l

BPE vs WordPiece

병합 기준 : 이웃한 쌍의 빈도 / 쌍 빈도 ÷ 두 조각 빈도의 곱

처음 분할 : 글자 / 첫 글자 그대로, 나머지에 ##

학습 결과 : 순서 있는 병합 규칙 / 어휘

새 단어 처리 : 병합 규칙을 학습 순서대로 적용 / 어휘에서 가장 긴 일치를 앞에서부터

수업 예제 첫 병합 : l + e (빈도 7) / h+##u (점수 0.25)

9번 병합 후 어휘 크기 : 21 (12 + 9) / 22 (13 + 9)

시험 포인트

대괄호 = 글자 한 칸의 선택, ^는 대괄호 안 첫 자리에서만 부정, \d \w \s의 대문자 = 반대

. 임의 글자, ? 0\~1번, * 0번 이상, + 1번 이상, |는 우선순위 최저 → 범위는 괄호

false negative = 못 잡음, false positive = 잘못 잡음 → 한쪽을 고치면 다른 쪽이 늘 수 있음

괄호 = 묶기 + 저장, \1에는 실제로 매치된 인스턴스, (?:)는 저장 X, (?!)는 글자를 소비하지 않음

lemma = 기본형, wordform = 활용된 표면 형태, type = 서로 다른 단어, token = 문장에 나온 인스턴스

예문 token 15 / type 13, 기준에 따라 14와 12, 11

Heaps' law , 는 보통 0.67과 0.75 사이

단어 단위 = unknown 문제, 글자 단위 = 의미 없는 조각 + 긴 시퀀스 → 서브워드가 절충, 분할은 데이터 빈도로 학습

BPE : 가장 자주 이웃하는 쌍을 병합 반복, 쌍 빈도에 단어 빈도를 곱함, 동점이면 먼저 나온 쌍

  • 최종 어휘 크기 = 처음 글자 수 + 병합 횟수, 새 단어는 병합 규칙을 학습 순서대로 적용
  • 수업 연습의 답 = ant

WordPiece : 점수 최대 쌍을 병합, 나머지 글자에 ##, 새 단어는 가장 긴 일치를 앞에서부터

문제 3
