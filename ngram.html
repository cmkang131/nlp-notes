2026-09-22, 09-29, 10-01 앞부분 · 슬라이드 N-gram LM (p.1–70)

언어 모델이란

n-gram : 아주 오래된 LM, 예전엔 대안이 없어서 꽤 좋은 방법이었음

지금 배우는 이유 → train/test set, perplexity, sampling, smoothing을 한 번에 익힐 수 있음

다음 단어 맞히기

사람은 빈칸 단어 후보를 쉽게 떠올림

  • A cat is sitting on the ___ → pillow, chair, couch, table
    I like apple, but I ___ like pear → but 때문에 don't
    I turned on the ___ to watch news → watch 때문에 radio는 X, TV

문맥이 많을수록 예측이 쉬워짐

기계에겐 복잡하고 당혹스러운(perplexed) 일 → 뒤의 perplexity로 이어짐

language model (LM) : 다음 단어마다 확률을 주는 시스템 → 문장 전체의 확률도 줄 수 있음

어디에 쓰나

  • 맞춤법·문법 : Their are → There are<br>음성 인식 : soonish vs bassoon dish 중 그럴듯한 쪽
    LLM : 다음 단어 예측을 반복해 글을 만듦 (left-to-right, autoregressive)

언어를 이해시키는 방법 = 다음 단어를 예측하도록 훈련

LM이 계산하는 두 가지

왼쪽 : 단어 열 전체의 확률
오른쪽 : 앞 단어들이 주어졌을 때 다음 단어의 확률
둘은 chain rule로 연결됨 (오른쪽을 곱하면 왼쪽)

그냥 세면 안 되는 이유

count로 나누기

: corpus에서 그 단어 열이 나온 횟수

문제 : 가능한 문장이 너무 많음 → 긴 문장은 corpus에 거의 안 나옴

  • 안 나온 문장은 전부 확률 0
    그럴듯한 문장과 단어를 섞은 문장을 구분 못 함
    분모까지 0이면 아예 정의가 안 됨

같은 뜻을 여러 문장으로 쓸 수 있음 → 정답 문장이 하나가 아님 → sparsity

chain rule

: 1번째부터 번째 단어까지

예 : = 5개 항의 곱

다음 단어 예측 = 문장 확률 계산

한계 : 마지막 항의 조건이 문장 거의 전부 → 여전히 corpus에 없음

Markov 가정과 n-gram

Markov assumption : 바로 앞 몇 단어만 봄 (매우 강한 단순화)

: n-gram 크기 = 문맥 개 + 예측 단어 1개

bigram이면

I saw a cat on a mat의 mat, 모델별 문맥 단어 수와 확률

  • unigram : 0개,
    bigram : 1개,
    trigram : 2개,
    4-gram : 3개,

문장 맨 앞처럼 앞 단어가 모자라면 있는 만큼만 씀

n-gram의 한계

long-distance dependency 처리 불가

  • The soups that I made from that new cookbook I bought yesterday ___ amazingly delicious
  • 주어는 soups → were가 정답
  • 앞 몇 단어(cookbook I bought yesterday)만 보면 was를 고르기 쉬움

비슷한 뜻의 새 문장 처리 불가 → 단어를 기호로만 셈

해결 : neural LM (긴 문맥, embedding으로 유사 단어 관계)

확률 추정 (MLE)

MLE와 문장 경계 토큰

MLE : training corpus에서 센 상대 빈도
  • 분자 : 두 단어가 붙어 나온 횟수
    분모 : 앞 단어가 나온 횟수 (뒤에 오는 모든 단어의 합과 같음)

<s> : 문장 시작 (SOS), </s> : 문장 끝

  • <s>가 있어야 첫 단어도 로 씀
    </s>가 있어야 길이가 다른 문장 전체에 대해 확률 합이 1
  • trigram은 앞에 <s> 두 개

I'm vs I am → 다른 토큰열로 셈, 모델은 뜻이 같은지 모름

training / dev / test set

training : 파라미터 학습, n-gram에서는 count를 세어 확률 생성, 학습 때
dev (validation, held-out) : 설정 고르고 조정, n-gram에서는 interpolation λ 결정, 여러 번
test : 최종 성능 보고, n-gram에서는 최종 perplexity, 마지막 한 번
test set : 학습에서 안 본 데이터 → generalization 측정
training on the test set : test 문장에 인위적으로 높은 확률 → bad science

test 점수가 갑자기 99% → 오염(contamination) 의심, 사실상 cheating
리더보드 대회가 test 정답을 공개하지 않는 이유
test set으로 여러 번 평가 → test에 맞춰 조정하게 됨 → dev set이 필요

Perplexity

좋은 LM의 기준

실제 문장엔 높은 확률, word salad엔 낮은 확률

Shannon game : Once upon a ___ → time .9, dream .03, midnight .02, and 10⁻¹⁰⁰

unigram은 이 게임에 약함 → 문맥 없이 흔한 단어(and)에 높은 확률

좋은 모델 = 보지 못한 test set 전체에 높은 확률을 주는 모델

perplexity = 당황한 정도

정의

: 예측한 단어 수 (<s>는 X, </s>는 O)

역확률의 기하 평균 → 길이로 정규화

  • 정규화 안 하면 문장이 길수록 값이 커짐

범위 1 \~ ∞, 낮을수록 좋음

PP 최소화 = 확률 최대화

0\~9 숫자 균등 모델 → → 매 단계 선택지 10개인 셈
